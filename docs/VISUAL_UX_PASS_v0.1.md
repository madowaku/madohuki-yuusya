# VISUAL / UX PASS v0.1

## 0. Goal

『窓ふき勇者 / WINDOW HERO』を、説明の多いプロトタイプから、

**「城壁を見た瞬間に、あの窓へどう行くか考え始める」1画面の論理パズル**

へ寄せる。

今回の主役はコンテンツ追加ではなく、盤面の読みやすさ・操作の省力化・AHAの視覚化。

基本原則:

> **プレイヤーの手数は減らす。プレイヤーの思考量は増やす。**

既存の CLIMB → CLEAN → DISCOVER → OPTIMIZE は維持する。

---

## 1. Scope

v0.1 では以下を実装・検証する。

1. **小窓を多数・不規則配置した12窓前後の1画面レイアウト**
2. **外壁＋室内経路の表示**
3. **内掛け鎧戸**
4. **Smart Ladder Reposition**
5. **最小HUD**
6. **Undo**
7. **既存CLEAN演出・生成アートとの統合**

今回やらないもの:

- 新しいアイテム体系
- ショップ / 永続強化
- 戦闘
- 室内迷路、鍵、箱押し、敵
- 多数の新ギミック
- ローグライト進行
- ボス戦本実装

---

## 2. Screen Composition

基準解像度は 720×1280。360×800 でも成立させる。

### 盤面比率

画面の **85〜90%を城壁・窓・足場・ハシゴ** に使う。

常設HUDは最小限:

- 左上: FLOOR / STAGE
- 上中央: 必要窓の進捗
- 右上: Undo / Menu

大きな常設説明パネル、アイテム欄、常時表示のフック一覧は置かない。

### 盤面の第一印象

初見で以下が自然に目に入ること。

- 小さな窓が8〜14枚ほど散らばる
- 閉じた鎧戸が1〜2枚ある
- ベランダ / 足場が分断されている
- 1本のハシゴがある
- 高所または離れた場所に「どう行く？」と思う窓がある

窓は整然とした格子に並べず、高さ・左右位置・足場からの距離を意図的にずらす。

---

## 3. Window Visual Language

文字説明より状態の見た目を優先する。

### Normal Dirty

- 白〜灰色の汚れ
- 室内の気配がうっすら見える

### Clean

- 暖色の室内がはっきり見える
- CLEAN直後だけ短く光る
- 常時キラキラさせない

### Enterable Window

- CLEAN後、少し開く
- カーテン / 光 / 奥行きで「入れる」と伝える
- 専用テキストは原則不要

### Inner Shutter / 内掛け鎧戸

- 外側から明確に閉じて見える
- 外から操作した場合は短い「ガタッ」反応だけ
- 外からは開かない
- 別の入れる窓から室内へ回り込み、内側から開ける
- 一度開けたらそのステージ中は恒久開放

### Discovery Window

- 必須ではない窓に住人・猫・星見の蛾などを配置可能
- パズル必須情報と混同させない

---

## 4. Small Window / Large Hit Area

見た目の窓は現在より小さくしてよい。

ただし入力判定は小さくしない。

360px幅の端末で:

- 主要タップターゲットは **44×44px相当以上**
- 見た目より広い透明ヒット領域を許可
- 近接する窓 / フック同士のヒット領域は重ねない
- 候補が密集する場合は、表示位置より入力優先順位を明示的に管理する

「小さく見える」と「押しにくい」を混同しない。

---

## 5. Interior Route

室内へ入っても別画面へ切り替えない。

### Transition

1. 入れる窓から勇者が入る
2. 外壁全体を少し暗くする
3. 現在の室内区画だけ壁を半透明化
4. 内部通路を暖色で表示
5. 勇者が室内を移動
6. 鎧戸を内側から開ける / 別窓から外へ出る

### Spatial Continuity

- 外に置いたハシゴは薄く見えたまま
- 外壁の窓位置と室内の出口位置を一致させる
- カメラ切替はしない
- プレイヤーが「盤面の裏側を歩いている」と理解できること

### 室内でやらないこと

室内には独立した新パズルを置かない。

室内の役割は、

**外壁上では直接つながっていない2点以上を短い経路でつなぐこと**

だけ。

---

## 6. Smart Ladder Reposition

通常の「回収」を事務操作にしない。

### UX Rule

> 判断のない回収は自動。  
> 判断のある「残す / 動かす」は盤面選択として残す。

### Basic Flow

既設ハシゴがあり、プレイヤーが合法な新しい設置先を選んだ場合:

1. 必要なら勇者が回収可能地点へ自動移動
2. ハシゴを自動回収
3. 運搬
4. 新しい場所へ再設置

プレイヤーは「回収」ボタンを毎回押さない。

### Preserve Meaningful Placement

- 新しい設置先を選ぶまで、既設ハシゴはその場に残る
- 帰路 / 橋として残すことに意味がある問題は壊さない
- 「移設すると現在の道が消える」ことは配置プレビューで視覚的に示す
- 既設ハシゴをタップした場合は登る / 渡るを優先する

### Placement Mode

常時すべてのフックを発光させない。

ハシゴ / 設置操作を開始した時だけ、現在状態で合法な候補を淡く表示する。

- 縦: 上下接続として読めるプレビュー
- 横: 橋として読めるプレビュー
- 選択中は半透明ハシゴを表示

---

## 7. Undo

硬い論理パズル化に合わせ、Undo を主要UXにする。

### Requirement

直前の意味あるゲーム状態へ1手戻せること。

最低対象:

- ハシゴ設置 / 移設
- 鎧戸開放
- 仕掛けによる常設経路開通
- 必要ならCLEAN完了状態

清掃ジェスチャそのものを何度もやり直させない。

Undo の目的は、

**試行錯誤のコストを下げ、考え直す楽しさを残すこと。**

---

## 8. CLEAN UX

CLEANは別画面・別モードに見せない。

1. 届く窓を選ぶ
2. 勇者が自動で適切な位置へ寄る
3. その場でスクイージー操作
4. 最後の少量は既存のスナップ清掃でピクセル探しを防止
5. キュッ → 光 → 室内 / 住人 / 経路をReveal

CLEAN後の変化がパズルに関係する場合は、エフェクト後すぐに盤面変化を見せる。

## 9. Visual Hierarchy

色に状態を語らせる。

- 未攻略の城壁: 青紫 / 低彩度
- CLEAN済み室内: 黄〜橙の暖色
- ハシゴ: 明るい木色、城壁から明確に分離
- 鎧戸: 暗い木 / 金属
- 新規開通経路: 金色を短時間だけ使用
- Hero: 小さめ。マント・スクイージー・動きで識別
- UI: 城壁より目立たせない

ゲームが進むほど暗い壁面に暖色の窓が増える。

## 10. Prototype Stage for This Pass

まず **1面のみ** を高密度化して検証する。

目安:

- 窓: 10〜12
- 通常窓: 5〜7
- 入れる窓: 1〜2
- 内掛け鎧戸: 1〜2
- 発見窓: 0〜1
- 可動ハシゴ: 1本
- 外部の分断: 2か所以上
- 室内接続: 1系統

狙うAHA:

1. 縦梯子を横橋として使う
2. ハシゴを残したまま窓から室内へ入る
3. 別窓の鎧戸を中から開ける
4. 開いた出口を使って外壁上の経路を短縮する
5. ハシゴを再び移設して上へ進む

新アイテムは使わない。

## 11. Interaction Feedback

### Ladder Place
- 「ガシャン」
- 1〜2px程度の短い揺れ

### Failed Shutter From Outside
- 「ガタッ」
- 鎧戸が数px動いて戻る
- 長文説明なし

### Open Shutter From Inside
- 明確な「ガチャッ」
- 暖色光が差す
- 外壁側の見た目も即更新

### New Permanent Route
- 0.4〜0.8秒程度
- 金色の継ぎ目 / 光が一度走る
- その後は通常の石・足場表現へ戻す

### CLEAN
- 既存のキュッ + 短いSparkle
- Revealの主役は窓の中身

## 12. Stage Transition Direction

v0.1で本実装必須ではないが、画面設計は将来これを許容すること。

ステージクリア後にメニューへ切らず、

1. 上端の出口 / フックが開く
2. 勇者がハシゴを掛ける
3. 上へ登る
4. カメラが上スクロール
5. 次の階の窓群が現れる

塔を本当に登り続ける感覚を最終形とする。

## 13. Accessibility / Mobile

720×1280 と 360×800 で確認。

- 主要タップ領域44px相当以上
- HUDが窓やフックに被らない
- 小窓の見た目を維持しつつ入力判定を確保
- マウス / タッチの操作意味を一致
- 端末での清掃ドラッグを優先
- フォーカス喪失時の既存Pause動作を維持

## 14. Acceptance Criteria

### Visual
- [ ] 1画面を見た時、城壁と窓がUIより先に目へ入る
- [ ] 10〜12窓でも各窓の状態を識別できる
- [ ] CLEAN前後が一瞬で判別できる
- [ ] 鎧戸と入れる窓を長文説明なしで区別できる
- [ ] 室内中も外のハシゴ位置を把握できる

### UX
- [ ] 通常プレイで「回収」忘れによる無意味な往復が発生しない
- [ ] 新設置先を選ぶと必要な回収・運搬・再配置が自動でつながる
- [ ] ハシゴを残す判断はプレイヤー側に残る
- [ ] Undoで試行錯誤をやり直せる
- [ ] 外から鎧戸を触ると「外から開かない」ことを演出だけで推測できる

### Puzzle
- [ ] ハシゴ1本だけで縦 / 横 / 残置 / 再配置の判断がある
- [ ] 室内ルートが最短経路の判断に影響する
- [ ] 新アイテム説明なしでAHAが成立する
- [ ] 合法な全状態から詰まない、またはUndoで安全に復帰可能
- [ ] 独立solverで最少設置数を検証できる

### Technical
- [ ] 720×1280 mouse完走
- [ ] 360×800 touch完走
- [ ] UI overlap / offscreen 0
- [ ] runtime warning / error 0
- [ ] Web export完走
- [ ] itch.io buildを壊さない

自動テストでは以下を評価できないので、初見試遊で確認する。

1. 説明なしで「鎧戸は中から開ける」と気づくか

## 17. Stop Conditions

以下が起きたら新コンテンツ追加を止め、UXを直す。

- 小窓が押しにくい
- 設置候補が多すぎて盤面が読めない
- Smart Ladderが勝手に判断したように感じる
- 室内へ入ると位置関係を見失う
- Undoが状態不整合を起こす
- CLEANが経路思考を頻繁に中断しすぎる
- 12窓が単なる作業量に感じる

目標は「窓を増やす」こと自体ではない。

**窓が増えたことで、経路を読む時間が面白くなること。**
